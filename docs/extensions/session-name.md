# Session Name：会话命名

Session Name 根据当前对话给会话生成一个简短、便于检索的标题。每个会话最多自动请求两次命名，其余时候由你手动生成。

## 命令

- `/session-name`：等当前工作空闲后，根据当前对话直接生成新标题。成功时显示新标题，这个标题按手动标题对待，之后不再自动改名；失败会提示原因并保留当前标题。手动生成不会重置或消耗自动命名次数。
- `/session-name config`：打开菜单，选择跟随主会话或独立模型／思考等级，启用／关闭自动命名或设置第二次自动命名前的输入数。菜单标题显示当前模型模式及本会话剩余的自动命名次数；当前标题受保护时显示自动命名已暂停。取消不保存。

没有专属快捷键。标题仍由 Pi 保存并用于会话列表和终端标题，扩展不增加新的底栏或忙闲标题动画。

## 自动命名的两次机会

默认开启自动命名，N 为 8。

1. 第一条可确认的有效用户输入处理结束后，自动生成第一次标题。
2. 首条输入之后再累计 N 条有效输入（默认即第 9 条输入处理结束后），自动生成第二次标题。
3. 之后本会话不再自动命名，需要更新时运行 `/session-name`。

次数属于整个会话：`/reload`、恢复会话、切换分支或修改配置都不会补发次数。已经开始的自动请求即使失败或被取消（例如你在它完成前又发了新消息、切换分支或改名），也算用掉一次，不会自动补偿；第一次失败不影响第二次按输入数触发。用户 abort 的那次结束不会发起自动命名，也不消耗次数，等下一次正常结束再尝试。

普通输入、实际交付的 steering 和 follow-up 可以计数；斜杠命令（含 skill／template）、插件注入、工具循环以及尚未交付的排队消息不计。被其他插件改写的输入或重复文本有歧义时可能少计，启用前已有的历史消息也不计，因此 N 不是所有插件组合下精确的“模型回合数”。已交付并处理结束的输入即使主请求失败也可计数。

自动命名失败时，提示会说明原因，以及是还剩一次自动机会还是本会话自动命名已结束。

## 手动标题不会被抢走

当前标题是手动设置的，自动命名就不再改它：包括用 Pi 的 `/name` 等入口改名，以及运行 `/session-name` 手动生成的标题。已有但来源不明的标题也会保护。被保护期间到点的自动机会不会发起请求，也不会被消耗；需要新标题时运行 `/session-name`。

命名状态无法恢复时，会话重新获得两次自动机会；手动和来源不明的标题仍受保护。

标题是整个会话共享的，不随分支分别命名。新输入、换分支、改名或关闭会话后，未完成请求的迟到结果不会覆盖当前标题；不保证发现其他进程直接改写会话文件的情况。

## 配置

配置全局保存在 `~/.pi/agent/session-name.json`，目录随 `PI_CODING_AGENT_DIR`：

```json
{
  "modelMode": "follow",
  "automatic": true,
  "interval": 8
}
```

`modelMode` 为 `follow`（跟随主会话）或 `custom`（独立配置）。没有模型设置时默认跟随；只填写独立 `model`／`thinking` 而不写模式时，按独立配置处理。独立模式示例：

```json
{
  "modelMode": "custom",
  "model": "provider/model-id",
  "thinking": "off",
  "automatic": true,
  "interval": 8
}
```

`model` 必须替换为已注册、已认证的文本模型；`thinking` 必须是该模型支持的显式等级，可选 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。

推荐通过 `/session-name config` 修改：

- **Follow main session**：同时跟随主会话模型和思考等级，保留已有独立设置，方便以后切回。
- **Set model**：选择已认证的文本模型并切换到独立模式；已有独立思考等级受支持则保留，否则继续选择思考等级，两步一起保存，任一步取消都不写入。
- **Set thinking**：为已配置的独立模型选择受支持的思考等级，并使用独立模式；尚无可用独立模型时提示先 Set model。
- **Enable automatic naming / Disable automatic naming / Set interval**：开启／关闭自动命名、修改输入间隔。

`automatic` 是布尔值；`interval` 是首条输入之后、第二次自动命名之前需要的有效输入数，接受 1–10000 的整数。没有项目或单会话覆盖，也没有专属环境变量。手改文件后在 Pi 中 `/reload`。

文件缺失时使用默认值。坏 JSON 或非法配置会提示并暂停命名。模型字段可通过菜单重新选择模型或切回跟随来修复；手改文件后 `/reload`。无法解析或不是对象的 JSON 必须手动修复，菜单不会覆盖。菜单保存会重新读取配置，保留未知字段，并拒绝覆盖已有的非法自动开关或输入间隔。预设不会强制发放此文件，避免同步重置个人选择。关闭 `automatic` 只停止自动命名（并取消进行中的自动请求），不会消耗未开始的机会；重新开启后只继续使用尚未用掉的机会。手动 `/session-name` 始终可用。

## 模型、内容与费用

命名是一次额外的模型请求。默认跟随请求发起时主会话的模型和思考等级，也可以独立配置；两种模式都不改变主对话的设置。参数在请求发起时捕获，之后切换主模型或保存模型设置不会替换已发起请求的参数。独立模型不可用、未认证、不支持文本或指定思考等级时会报错，不回退主模型；provider 不支持请求时也不自动换模型或降级。默认总等待上限为 120 秒。每次都直接根据对话生成标题，不参考现有标题，结果碰巧与原标题相同也属正常。

命名材料与 [Recap](recap.md) 使用同一套上下文整理方式，取请求时当前分支的有效上下文：用户／助手文字、已有的压缩和分支摘要为主，工具调用、工具／命令执行结果和插件上下文作为辅助（每条工具或执行结果最多 100 个字符）。不发送图片或 thinking，不恢复已压缩的原始历史，也不会先另调模型总结。命名材料固定上限为 32000 字符，超出时先从旧到新删除辅助内容，再截掉最早的对话正文并标明省略；它不读取 Recap 的配置。没有可用对话内容时不会发起请求。

长对话或高思考等级的命名成本不固定。想减少请求可以关闭自动命名后只手动生成。不响应取消的第三方 provider 请求可能继续内部执行，关闭或取消不能保证它立即停下，但迟到结果不会写回标题。
