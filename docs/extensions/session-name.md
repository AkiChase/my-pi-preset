# Session Name：会话命名

Session Name 根据当前对话给会话生成一个简短、便于检索的标题。每个会话最多自动请求两次命名，其余时候由你手动生成。

## 命令

- `/session-name`：等当前工作空闲后，根据当前对话直接生成新标题。成功时显示新标题，这个标题按手动标题对待，之后不再自动改名；失败会提示原因并保留当前标题。手动生成不会重置或消耗自动命名次数。
- `/session-name config`：打开菜单，启用／关闭自动命名或设置第二次自动命名前的输入数。菜单标题会显示本会话剩余的自动命名次数，当前标题受保护时显示自动命名已暂停；`Enable automatic naming`、`Disable automatic naming`、`Set interval` 分别对应三项操作，取消不保存。

没有专属快捷键。标题仍由 Pi 保存并用于会话列表和终端标题，扩展不增加新的底栏或忙闲标题动画。

## 自动命名的两次机会

默认开启自动命名，N 为 8。

1. 第一条可确认的有效用户输入处理结束后，自动生成第一次标题。
2. 首条输入之后再累计 N 条有效输入（默认即第 9 条输入处理结束后），自动生成第二次标题。
3. 之后本会话不再自动命名，需要更新时运行 `/session-name`。

次数属于整个会话：`/reload`、恢复会话、切换分支或修改配置都不会补发次数。已经开始的自动请求即使失败或被取消（例如你在它完成前又发了新消息、切换分支或改名），也算用掉一次，不会自动补偿；第一次失败不影响第二次按输入数触发。用户 abort 的那次结束不会发起自动命名，也不消耗次数，等下一次正常结束再尝试。

普通输入、实际交付的 steering 和 follow-up 可以计数；斜杠命令（含 skill／template）、插件注入、工具循环以及尚未交付的排队消息不计。被其他插件改写的输入或重复文本有歧义时可能少计，启用前已有的历史消息也不计，因此 N 不是所有插件组合下精确的“模型回合数”。已交付并处理结束的输入即使主请求失败也可计数。

自动命名失败时，提示会说明原因，以及是还剩一次自动机会还是本会话自动命名已结束。

## 手动标题不会被抢走

当前标题是手动设置的，自动命名就不再改它：包括用 Pi 的 `/name` 等入口改名，以及运行 `/session-name` 手动生成的标题。已有但来源不明的标题也会保护。被保护期间到点的自动机会不会发起请求，也不会被消耗；需要新标题时运行 `/session-name`。

旧版本留下的命名状态或无法读取的状态不会沿用，会话重新获得两次自动机会；手动和来源不明的标题仍受保护。

标题是整个会话共享的，不随分支分别命名。新输入、换分支、改名或关闭会话后，未完成请求的迟到结果不会覆盖当前标题；不保证发现其他进程直接改写会话文件的情况。

## 配置

配置全局保存在 `~/.pi/agent/session-name.json`，目录随 `PI_CODING_AGENT_DIR`：

```json
{
  "automatic": true,
  "interval": 8
}
```

`automatic` 是布尔值；`interval` 是首条输入之后、第二次自动命名之前需要的有效输入数，接受 1–10000 的整数。没有项目或单会话覆盖，也没有专属环境变量；建议通过 `/session-name config` 保存。手改文件后在 Pi 中 `/reload`。

文件缺失时使用默认值。坏 JSON 或非法字段会提示并暂用默认值；无法解析或不是对象的 JSON 必须先手动修复，菜单不会覆盖。合法 JSON 对象中的非法字段可以通过配置菜单重新保存修复。预设不会强制发放此文件，避免同步重置个人选择。关闭 `automatic` 只停止自动命名（并取消进行中的自动请求），不会消耗未开始的机会；重新开启后只继续使用尚未用掉的机会。手动 `/session-name` 始终可用。

## 模型、内容与费用

命名是一次额外的模型请求，跟随当前模型和当前思考等级，不改变主对话的设置，也没有单独的命名模型配置。provider 不支持当前请求时会报失败，不自动换模型或降级。默认总等待上限为 120 秒。每次都直接根据对话生成标题，不参考现有标题，结果碰巧与原标题相同也属正常。

命名材料与 [Recap](recap.md) 使用同一套上下文整理方式，取请求时当前分支的有效上下文：用户／助手文字、已有的压缩和分支摘要为主，工具调用、工具／命令执行结果和插件上下文作为辅助（每条工具或执行结果最多 100 个字符）。不发送图片或 thinking，不恢复已压缩的原始历史，也不会先另调模型总结。命名材料固定上限为 32000 字符，超出时先从旧到新删除辅助内容，再截掉最早的对话正文并标明省略；它不读取 Recap 的配置。没有可用对话内容时不会发起请求。

长对话或高思考等级的命名成本不固定。想减少请求可以关闭自动命名后只手动生成。不响应取消的第三方 provider 请求可能继续内部执行，关闭或取消不能保证它立即停下，但迟到结果不会写回标题。
