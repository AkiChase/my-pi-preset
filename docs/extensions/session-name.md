# Session Name：会话命名

Session Name 根据当前对话给会话取一个简短、便于检索的标题。已有标题仍准确时可以保持不变，不会为了刷新而强行换一个。

## 命令

- `/session-name`：等当前工作空闲后重新评估标题。成功时显示新标题并恢复自动管理；失败会提示并保留当前标题。
- `/session-name config`：打开菜单，启用／关闭自动命名或设置评估间隔。菜单中的 `Enable automatic naming`、`Disable automatic naming`、`Set interval` 分别对应这三项操作；取消不保存。

没有专属快捷键。标题仍由 Pi 保存并用于会话列表和终端标题，扩展不增加新的底栏或忙闲标题动画。

## 自动更新

默认开启自动命名，间隔为 8 次有效用户输入。

没有标题的会话会在第一批可确认的用户输入处理结束后尝试命名。之后每累计 N 次有效输入再评估一次，即使原标题不变，成功评估也会重新计算下一次间隔。

普通输入、实际交付的 steering 和 follow-up 可以计数；斜杠命令（含 skill／template）、插件注入、工具循环以及尚未交付的排队消息不计。历史输入、被其他插件改写的输入或重复文本有歧义时可能少计，因此 N 不是所有插件组合下精确的“模型回合数”。已交付并处理结束的输入即使主请求失败也可计数；用户 abort 的那次结束不会自动发起命名。

命名失败会显示提示，再累计 N 次有效输入后自动重试，不会在同一个失败点反复请求。也可以随时用 `/session-name` 手动重试。

## 手动标题不会被抢走

用 Pi 的 `/name` 或其他入口改名后，自动命名暂停覆盖。已有但来源不明的标题也会保护。想再次交给自动管理，运行 `/session-name` 并让这次刷新成功。

标题是整个会话共享的，不随分支分别命名。新输入、换分支、改名或关闭会话后，未完成请求的迟到结果不会覆盖当前标题；不保证发现其他进程直接改写会话文件的情况。

## 配置

配置全局保存在 `~/.pi/agent/session-name.json`，目录随 `PI_CODING_AGENT_DIR`：

```json
{
  "automatic": true,
  "interval": 8
}
```

`automatic` 是布尔值，`interval` 接受 1–10000 的整数。没有项目或单会话覆盖，也没有专属环境变量；建议通过 `/session-name config` 保存。手改文件后在 Pi 中 `/reload`。

文件缺失时使用默认值。坏 JSON 或非法字段会提示并暂用默认值；无法解析或不是对象的 JSON 必须先手动修复，菜单不会覆盖。合法 JSON 对象中的非法字段可以通过配置菜单重新保存修复。预设不会强制发放此文件，避免同步重置个人选择。关闭 `automatic` 只停止自动评估，手动 `/session-name` 仍可用。

## 模型、内容与费用

命名是一次额外的模型请求，跟随当前模型和当前思考等级，不改变主对话的设置，也没有单独的命名模型配置。provider 不支持当前请求时会报失败，不自动换模型或降级。默认总等待上限为 120 秒。

它使用当前分支对话中的用户／助手文字及已有的压缩、分支摘要，不发送图片，也不把 thinking、工具调用／结果、插件状态和 shell 日志作为命名材料。不会先另调模型总结，也不会只截取最近几条消息。

长对话或高思考等级的命名成本不固定。想减少请求可以调大 N，或关闭自动更新后只手动刷新。不响应取消的第三方 provider 请求可能继续内部执行，关闭或取消不能保证它立即停下，但迟到结果不会写回标题。
