# Recap：会话回顾

Recap 在编辑器上方显示一句短回顾，帮助重新进入工作：先说明目标，再补当前进展、关键决定、阻塞或下一步。它不是长期记忆或完整报告，重要结论仍需核对对话和文件。

Recap 通过内置 [Widget Display](widget-display.md) 展示，在编辑器上方固定排在 Trellis 任务信息之前，不因生成或刷新顺序改变。请保持 Widget Display 启用；未接入的第三方 widget 与整个组合的相对位置仍由 Pi 决定。

## 命令

| 命令 | 用途 |
| --- | --- |
| `/recap` | 立即重新生成并显示回顾；运行中先等待空闲 |
| `/recap config` | 查看和修改模型、思考等级、自动开关、空闲时间及上下文预算 |

当前会话正在运行时，手动命令先等待空闲。新的对话输入或导航会取消等待及旧请求。显式 `/recap` 每次重新请求模型，使用当前配置；恢复会话和自动生成可以复用仍有效的已存回顾。

## 自动回顾

- 当前会话正常结束后，默认完整等待 5 分钟再尝试一次；运行中的静默时间不计入这 5 分钟。
- 对话输入、正文/thinking 增量及工具活动会使旧请求失效。运行、重试和排队续跑期间不生成。
- 每个空闲窗口最多自动尝试一次，失败不会循环重试。
- 中止运行后不自动生成。无法确认输入处理或导航结束时，保守暂停，等下一次正常对话结束；也可手动 `/recap`。
- 后台任务本身不阻止回顾；通知触发当前会话续跑时，旧请求会被取消。
- 恢复会话时显示仍有效的已存回顾；缺失或过期且自动开启时尝试生成，不必等 5 分钟。空会话不请求。
- 关闭自动生成仍可手动使用，并恢复显示有效回顾。手动压缩后的自动检查最多安排一次；若检查时仍忙，等下一次正常对话或手动命令，不持续轮询。

这不是整个 Pi 或操作系统的空闲检测，不监听未提交的键入，也不保证覆盖所有命令、直接 `!` / `!!` 或第三方插件内部等待。

## 模型与配置

配置文件为 agent 根目录的 `recap.json`，默认 `~/.pi/agent/recap.json`，跟随 `PI_CODING_AGENT_DIR`。必须显式设置模型和思考等级，缺任一项都不能生成；不跟随主会话模型，不选择默认模型，也不静默回退。

```json
{
  "model": "provider/model-id",
  "thinking": "high",
  "automatic": true,
  "idleMinutes": 5,
  "maxContextChars": 32000
}
```

示例中的模型需要替换为本机已注册、已认证的文本模型，思考等级也必须受该模型支持。可选等级为 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，并非每个模型都支持全部等级。

| 配置 | 默认值与限制 |
| --- | --- |
| `model` | 必需，`provider/model-id` |
| `thinking` | 必需，模型支持的显式等级 |
| `automatic` | `true` |
| `idleMinutes` | `5`，范围 0.01–1440 分钟 |
| `maxContextChars` | `32000`，整数 256–1000000 |

推荐通过 `/recap config` 修改：

- **Set model**：从已认证且支持文本输入的模型菜单中选择，不需要手填 `provider/model-id`。没有可用模型时提示先配置 provider，不写入配置。
- **Set thinking**：只列出已选模型支持的档位；尚未选好可用模型时提示先使用 Set model。
- 选择模型后，已有思考档位仍受支持则保留；缺失或不兼容时接着展示思考档位菜单，两步完成后一起保存。任一步取消都不写入。

保存保留未知字段；损坏 JSON 不会被覆盖。修改影响后续请求，正在进行的请求使用已捕获的参数。重新开启自动功能不会复活已失败的空闲窗口。此文件由插件拥有，不由 preset 的 `files` 配置同步。

## 内容、成本与限制

使用当前分支的有效上下文，尊重已有压缩，不补发压缩前原始历史。正文和已有摘要优先，工具结果每项最多 100 字符；总材料按 `maxContextChars` 限制，超限先省略较早工具信息，再裁减较早正文。thinking 和原始图片不发送。预算是字符数，不是精确 token 数。

生成会额外请求所选模型，可能产生费用，也会把相关会话内容发送给该服务。请求总截止时间为 120 秒；回顾为单行文字，目标约 160 字符、最多 240 字符。保存的数据不加入主会话模型上下文。

失败通知显示安全清理后的具体原因及保存后果，请求或正文处理失败不会覆盖已保存回顾；保存失败则显示持久化未确认的具体原因，内存会话可能已变化，不能保证磁盘与内存一致。取消、过期或迟到结果不向新上下文报告错误。回顾可能遗漏信息，不能替代验收。

编辑器上方的展示仅交互式 TUI 可用。RPC 可接收通知和配置对话框，但没有该 widget；print/JSON 模式的公开通知为空操作，不能保证可见错误提示。当前没有在线生成质量或所有终端组合的保证。
