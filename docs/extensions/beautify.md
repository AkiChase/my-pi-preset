# Beautify：工具与输入框美化

Beautify 把常用工具的调用和结果收成单行摘要，需要看正文时再展开；输入框保留上下横线，首行加上 `❯`，没有左右竖边框。

安装本预设后随扩展加载，不需要额外命令或配置文件。它只改变终端展示，不改变工具执行、返回给模型的内容或任务状态。

## 看工具结果

沿用 Pi 的工具展开键，默认是 `Ctrl+O`；改过键位时，以工具标题上的提示为准。也可以点击宿主的工具结果区域切换展开状态。

| 工具 | 折叠摘要 | 展开后 |
| --- | --- | --- |
| `read` | 路径、起始行、返回行数；有续读限制时标 `limited` | 路径、从 1 开始的行号和代码高亮；保留限制说明 |
| `bash` | 命令、传入的 timeout、输出行数；能识别的后台结果显示任务 ID | 本次返回的输出或错误、后台日志路径 |
| `find` | 搜索条件、已展示的文件数 | 按返回顺序分组显示目录与文件 |
| `grep` | 搜索条件、已展示的匹配行数 | 按文件显示行号、匹配行和上下文，能识别的匹配内容会高亮 |
| `process_manage` / `agent_manage` | 动作、任务描述／身份及可用的状态、耗时／用量、任务数、字节范围或匹配数 | 本次已经返回的输出、结果或错误；子 Agent 传了 `verbose` 时也显示返回的格式化对话 |

标题保留真实工具名，如 `process_manage` / `agent_manage`。窗口变窄时先保工具名，再缩短路径、命令或描述，次要统计可能隐藏。工具名本身也放不下时会截短。

摘要中的数量是本次返回或展示的数量，不一定是文件或搜索结果的总量。`read` 中很长的代码行会用 `›` 标记截短；需要更多内容时仍要让模型续读。展开后台 Bash 的返回只是在看启动信息，不表示后台命令已经完成。Bash 的 `ms call` 表示这次工具调用耗时，不是后台进程总耗时。

`process_manage` / `agent_manage` 只有在实际存在、且返回格式能识别时才使用上述摘要，覆盖 Bash、Monitor、子 Agent 和 workflow 的管理动作。未知格式保留原展示或使用普通文本预览，因此不保证所有返回都只有一行。展开只显示本次已返回的内容，不会另读日志或获取结果。等待中的临时输出与最终结果会区别显示；解除或取消结果等待不等于停止任务，`stop` 的报告也不保证执行已在同一瞬间退出。

图片仍由 Pi 显示。`edit`、`write`、`ls` 及其他未列出的工具保持原展示；`ask_user_question` 仍显示它的小写注册名，问卷交互不受 Beautify 接管。

## 输入框

`❯` 只出现在第一行，续行不重复；向上滚动到第一行不可见时也不会补一个新的提示符，原生隐藏行提示仍保留。原有工作状态的位置用于显示主会话阶段：`Loading` 表示尚未观察到生成内容，`Brewing` 表示正在生成内容，`Tooling` 表示正在处理工具，`Asking` 表示需要回答或确认，`Compacting` 表示正在压缩上下文。

通常显示一个原生旋转标记、一个状态词和该阶段耗时；状态切换重新计时，同阶段更新不重置。`Asking` 使用静态 `◇`，不显示耗时。状态颜色会有限增强，但等待变长不会变成错误提示，也不会加快动画。窗口变窄时优先隐藏耗时，极窄时只保留标记。

`Compacting` 从本次原生压缩提示首次出现开始计时，不是精确的压缩操作起点，重试后继续累计。原生重试、分支总结和压缩取消提示仍保留。问题 UI 临时替换输入框时保留原生交互，不另外显示一行 `Asking`；工具详情仍在工具卡片和任务面板中。准备交接或结束时清除阶段提示，不保留 `Done`。

编辑、撤销、粘贴和历史导航继续使用原来的按键。Beautify 本身不提供输入历史搜索；预设中的历史搜索由 `pi-input-history` 提供，预设键位是 `Alt+R`。任务面板和空输入框 `Down` 的行为见 [任务管理](task-composition.md)。

## 配置与限制

- 没有 Beautify 专属配置文件、斜杠命令或新快捷键。代码高亮固定使用 `one-dark-pro`，不会切换 Pi 的全局主题；未知语言、很长的文本或高亮失败时显示普通文本。
- 不增加路径补全、文件搜索、连续工具分组、用户消息前缀或第二套加载动画。阶段展示复用 Pi 原生 indicator；不兼容的宿主或编辑器保留原生状态。路径连续补全由 [独立扩展](at-path-completion.md) 提供。
- 不兼容的第三方编辑器可能保持原外观，并在加载日志里给出诊断。极窄窗口下仍可能遇到 Pi 原生布局限制，放大窗口后再查看。
- 没有额外的选区或剪贴板处理，不能保证从终端复制出的文本没有软换行。
