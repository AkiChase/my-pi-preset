# Trellis：任务生命周期

> 草稿：Trellis 尚未作为本预设的内置插件上线，本页描述迁入后的用法。

一次需要修改代码的工作就是一个任务。任务从规划开始，经过实施和检查，由你验收后归档。

```text
planning ──批准实施──▶ in_progress ──验收收尾──▶ 归档
```

只读的请求，比如“解释一下这段代码”“看看哪里要改”，Pi 直接回答，不建任务，也不改文件。决定要改时，再让 Pi 建任务。

## 1. 规划

告诉 Pi 要做什么，例如：

> 建一个任务，给任务面板加状态筛选，先写方案，不改代码。

Pi 会创建任务目录 `.trellis/tasks/<日期>-<名称>/`，状态为 `planning`，并写下：

- `prd.md`：要做什么、不做什么、怎样算完成。
- `design.md`：技术方案和取舍，复杂任务才有。
- `implement.md`：分阶段的实施计划和进度，复杂任务才有。

用[任务浏览器](#task-viewer)查看这些文档。有意见直接告诉 Pi 修改，确认后再进入实施。建任务、写方案都不等于批准实施，这一阶段 Pi 不会改产品代码。

## 2. 实施

方案没问题后告诉 Pi：

> 按这个计划实施。

任务进入 `in_progress`，Pi 开始改代码。复杂任务按 `implement.md` 分阶段进行，每完成一个阶段，Pi 先检查，再在本地提交这一阶段，然后继续下一阶段。

- 不想自动提交，就说“这次不要提交”。
- 实施过程中不会 push，也不会安装依赖，除非你明确要求。
- 范围有较大变化时，Pi 会先和你确认。

## 3. 中断后继续

任务绑定在 Pi 会话上：每个会话记录自己正在处理哪个任务。多个会话可以绑定同一个任务，切换一个会话的任务不影响其他会话。

**恢复原来的会话**（`pi -c` 或 `/resume`）时，绑定还在，直接说“继续”就行。

**新开的会话**没有绑定任何任务，Trellis 不会去猜你想继续哪个。告诉 Pi 是哪个任务即可，例如：

> 继续任务面板筛选那个任务。

Pi 会把这个任务绑定到当前会话，读取需求和实施记录，判断下一步：规划中就继续完善方案，实施中就从没做完的阶段接着做。不确定任务名时，先用[任务浏览器](#task-viewer)找一下。

这里有两个容易混的操作，由 Pi 替你执行：

| 操作 | 作用 |
| --- | --- |
| `task.py active <任务>` | 只把任务绑定到当前会话，不改任务状态，用于续接 |
| `task.py start <任务>` | 批准实施后启动任务，把 `planning` 改为 `in_progress` |

续接一个规划中的任务不会把它变成实施中，仍然要等你批准。

对话很长、上下文被压缩过，或者不确定做到哪一步时，可以输入 `/skill:trellis-start`，让 Pi 重新读取项目和任务状态。

## 4. 收尾

Pi 报告完成后，你确认结果没问题，再说：

> 验收通过，收尾。

或输入 `/skill:trellis-finish-work`。Pi 会把任务移到 `.trellis/tasks/archive/`，并在你的工作记录里写一段摘要。

任务做完不会自动归档，必须由你确认。

## 任务浏览器

```text
/trellis-task-viewer
```

打开一个全屏的任务浏览器，列出项目中所有未归档的任务。子任务排在父任务下面，当前会话的任务排在最前，并用 `*` 标出。

选中一个任务按 `Enter` 进入详情，可以在四页之间切换：

- **Overview**：任务名称、状态、路径、父子任务等基本信息。
- **PRD**、**Design**、**Implement**：对应的任务文档，没有的会提示缺失。

| 按键 | 列表中 | 详情中 |
| --- | --- | --- |
| `↑` `↓` | 选择任务 | 滚动文档 |
| `Enter` | 打开详情 | — |
| `←` `→` | — | 切换页面 |
| `r` | 刷新列表 | 重新读取文档 |
| `Esc` | 关闭浏览器 | 返回列表 |

浏览器只用来查看：不会修改任务，也不会切换当前会话的任务。在 Fullscreen 模式下，也可以用鼠标滚轮滚动文档。浏览器需要在交互终端中使用。

## 子任务

大的工作可以拆成子任务，例如“把筛选交互拆成一个子任务”。子任务只用来组织和查看进度，不会自动按顺序执行，也不会随父任务一起完成。
