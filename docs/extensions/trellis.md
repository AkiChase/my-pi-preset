# Trellis：项目任务与工作流

Trellis 给 Pi 加上一套按任务推进的开发流程。项目规范、每个任务的需求和计划、实施进度都保存在项目的 `.trellis/` 目录里，跟着仓库走，而不是只留在聊天记录里。

使用 Trellis 后，Pi 修改代码前会先建任务、写方案，经你批准再动手；每完成一个阶段先检查再提交；做完由你验收后归档。只读的问题，比如解释代码、查找问题，仍然直接回答，不走这套流程。

默认任务行通过内置 [Widget Display](widget-display.md) 展示，在 Recap 下方、编辑器上方。请保持 Widget Display 启用；`status` 模式仍使用底部状态栏，不依赖 widget 展示。未接入的第三方 widget 与整个组合的相对位置仍由 Pi 决定。

## 快速开始

1. 在项目根目录启动 Pi，输入 `/trellis-init` 初始化项目，见[初始化](trellis/initialization.md)。
2. 按提示 `/reload` 或开新会话，加载 Trellis 的技能和角色。
3. 直接告诉 Pi 你要做什么。任务怎样从规划走到收尾，见[任务生命周期](trellis/tasks.md)。

## 常用入口

| 入口 | 用途 |
| --- | --- |
| `/trellis-init` | 初始化项目、设置身份、更新资源、检查问题 |
| `/trellis-task-viewer` | 打开任务浏览器，查看任务和文档 |
| `/skill:trellis-start` | 开始或恢复会话，让 Pi 了解项目规范和当前任务进度 |
| `/skill:trellis-finish-work` | 验收后归档任务并记录工作 |

日常不需要背命令，用自然语言说清楚意图即可，例如“先只看不改”“按这个计划实施”“这次不要提交”“验收通过，收尾”。

## 项目里保存了什么

| 位置 | 内容 |
| --- | --- |
| `.trellis/workflow.md` | 工作流程规则：什么时候规划、检查、提交，哪些操作要你批准 |
| `.trellis/spec/` | 项目的长期开发规范，Pi 写代码前会读 |
| `.trellis/tasks/` | 每个任务一个目录，包含需求、方案和进度 |
| `.trellis/workspace/` | 每个人的工作记录 |
| `.pi/agents/` | 实现、检查、研究三个角色 |

规范和任务是两回事：规范是长期遵守的规则，比如“配置写入要保留用户的自定义项”；任务是这一次要做的事，比如“给面板加一个筛选”。

## 角色

Trellis 提供三个专门的角色，主会话可以把工作交给它们：

| 角色 | 负责 |
| --- | --- |
| `trellis-implement` | 按批准的方案写代码，完成后自检 |
| `trellis-check` | 审查改动，修复范围内的明显问题，并跑相关检查 |
| `trellis-research` | 只读调研代码、接口和方案，不改产品代码 |

是否派发由 Pi 根据任务判断。范围清楚的小改动，主会话通常直接做；改动较大或需要独立审查时，再交给角色。你也可以直接要求，例如“实现完找一个独立的检查”。

角色做完把结果交回主会话，由主会话核对后提交。角色不会自己提交、归档，也不会再派发别的角色。

默认情况下，角色在当前项目目录里工作。需要把某个任务的修改隔离开时，可以让 Pi 为它创建单独的 Git worktree，默认放在项目的 `.worktree/` 目录。

## 任务显示

初始化后，编辑器上方会显示一行任务状态：

```text
▸ trellis(3) · 10-15-task-panel-filter · in_progress
```

括号里是项目中未完成的任务数，后面是当前会话正在处理的任务和它的状态。显示 `(?)` 表示读取失败，不代表没有任务。

启动 Pi 前可以用环境变量 `TRELLIS_PI_STATUS` 调整显示位置：默认 `widget` 显示在编辑器上方；`status` 放进底部状态栏；`off` 不显示，但不影响其他功能。
