# 对齐 subagent 详情页与主 Agent 的运行体验

## 最新授权修正：真实验收后的主页面对齐（优先于下文旧阶段3规则）

用户通过两张真实截图拒绝独立参数入口、附加提示行及通用包装的不同风格，并明确批准修正方案。
- 删除 View parameters 与参数reader分支，点击卡片只统一展开/收起；Ctrl+O沿主Agent语义切换已加载工具统一展开，标题提示复用实际快捷键。
- read/bash/grep/find 直接沿用主页面工具renderer的renderCall/renderResult/shell；write/edit沿主页面native内容/diff布局，edit禁止现场文件IO，只用已返回diff。
- 撤销bash默认3行及write/edit强制摘要策略，默认行为以主页面实际renderer为准；不新增固定Arguments/Output分区，不保证专用renderer额外暴露其未显示参数。
- 正常完成不添加多余Completed统计；时长接入主标题统计，失败/中断在兼容原状态位置表示；源数据缺失/截断才明确提示，无常驻complete标签。
- 顶部终态、底部总耗时、消息队列及所有执行/消费/分页/预算边界保留。先完整Pi主页面与详情同工具/同参数/同结果/同宽度并排捕获再判断视觉完成；外部TUI harness不足以证明一致。
- 授权在现任务下实施、独立审查、验证与本地提交；不动并行beautify参数任务、个人配置、SDK或安装，不push/归档。


## 目标

用户在 subagent 详情页中能够判断当前工具执行了多久、追加消息是否仍在排队，并以接近主 Agent 页面的信息密度阅读工具调用与结果。保留详情页独立的分页、滚动和任务控制能力，不以嵌入整个主页面实现对齐。

## 授权与范围

- 用户已同意创建任务并进入规划，要求关注工具耗时、消息反馈以及默认显示行数三个方面。
- 用户已审阅完整交互方案并明确批准“可以，开工吧”。授权按 implement.md 分阶段实施、验证及主会话本地提交；不 push、不安装、不修改个人环境。
- 不安装依赖、不修改 SDK、不同步或 reload 个人运行环境、不 push、不归档其他任务。
- 保护其他会话已有的暂存、未暂存和未跟踪改动；实施前重新核查 Git 状态。

## 需求与证据

### R1：工具调用级运行状态与计时

- 当前主页面通过 `extensions/beautify/tool-clock.ts:33–56` 按调用 ID 记录执行中 elapsed，并在完成后优先采用宿主 execution duration。
- subagent runner 在 `extensions/agent-tasks/src/agent-runner.ts:1193–1197,1323–1324` 仅传递 start/end 和 toolName；manager 在 `extensions/agent-tasks/src/agent-manager.ts:871,1311` 保存单一 activity 字符串。
- source 的 `extensions/agent-tasks/src/source.ts:165` 输出 Agent 总耗时；`extensions/task-ui/presentation.ts:93` 将工具名与总耗时放在同一状态行，无法分辨调用耗时。
- 需要为当前工具显示执行状态、调用级耗时，并与 Agent 总运行时长明确区分；按 toolCallId 关联同名或并发调用。
- 终止、失败、resume 和迟到事件不能使旧调用计时继续增长或串到新执行。历史缺失的计时不得通过消息时间差猜造。

### R2：待处理消息与发送反馈

- `extensions/task-ui/panel.ts:284–289` 在提交时关闭输入框，仅对同步拒绝发出警告，成功无反馈。
- `extensions/agent-tasks/src/agent-manager.ts:1349–1359` 把准备前的消息放入 pendingSteers，准备后的消息交给 session.steer，且吞掉异步拒绝。
- 已安装 SDK 支持 queue_update、getSteeringMessages/getFollowUpMessages；当前 subagent source/UI 未订阅或投影该队列。
- `extensions/agent-tasks/src/source.ts:88–108,224–225` 的 Messages 区域来自 mailbox 提问/回复/通知，不是普通 steering 待处理队列。
- 需要在追加消息后显示实际待处理内容，覆盖 session 未准备好与已运行两种状态；入队不代表 Agent 已读或已处理。
- 消息被会话接收后从待处理区移除，不能与普通 User 消息重复显示；投递失败必须可见。
- 消息显示按选中 task/run 隔离，返回列表、重进详情、滚动历史和 resize 不得丢失或串消息。

### R3：紧凑工具卡片与展开语义

- `extensions/task-ui/conversation.ts:9–10,75–95` 默认预览 5 个视觉行、展开最多 40 行，调用与结果分开显示。
- 主页面 `extensions/beautify/tools/read.ts:55`、`extensions/beautify/tools/shared.ts:44` 默认摘要不显示结果正文；通用卡片 `extensions/beautify/card-primitives.ts:139` 默认最多 3 行正文。
- 详情页需采用按工具区分的摘要/预览策略，减少调用与结果的重复标题；read/grep/find 默认摘要，通用输出默认紧凑预览。
- 折叠隐藏与源数据截断必须分别提示；保留按稳定条目 ID 展开、分页与滚动锚点，不声称已加载全部原始结果。

### R4：详情页及时呈现执行终态

- 用户澄清 R4 的主要问题是终态提醒不够明显，而不是声称后端没有感知状态；采用已确认的顶部固定单行背景变化方案（见已确认决策）。
- 初步源码观察仅为关联风险，不作为漏刷新已确认缺陷；实施仍需验证停止后旧 activity 和计时不误导。
- 源码已有 stop → notifyChanged → source → panel 更新链路，但 `extensions/task-ui/presentation.ts:89–97` 状态行仅用 glyph 表达生命周期，未显示明确的 Stopped/Completed/Failed 文本，且继续拼接 activity。
- `extensions/agent-tasks/src/agent-manager.ts:1526–1541` 的 abort 设置 stopped 并发布变化，但 activity 到 `settleRun`（同文件 1103–1116）才清除；停止后实际执行尚未退出期间可能仍显示旧工具 activity。
- 验证 UI 自身停止、父会话停止和自然完成等路径，区分后端未发布、显示未刷新与终态表达不足。详情页保持打开、保留输出和历史位置，状态明确变化，旧工具不再表现为 Running。
- 终态不能虚报所有底层资源已退出；若实际清理仍未完成，需用可核实的小型状态提示区分。

## 验收标准

- AC1（R1）：长时间工具执行时，详情页每秒更新该调用耗时，Agent 总耗时独立可辨；同名调用分别关联，结束/失败/停止后不继续计时，resume 不复用旧状态。
- AC2（R2）：发送一条或多条追加消息后立即能看到待处理内容与状态；准备前后队列有连续可见性，消息被接收后移出，异步拒绝有可见失败反馈。
- AC3（R2）：选中身份、滚动历史、重进详情和窗口尺寸变化不导致消息丢失、重复或跨 run 泄漏；查看详情不改变结果消费或 wait 所有权。
- AC4（R3）：read/grep/find 默认摘要，通用工具默认不超过 3 个正文视觉行；调用与结果不再无意义重复工具标题。
- AC5（R3）：点击展开/折叠可逆，提示准确区分显示层隐藏与源截断，保留分页和滚动锚点。
- AC6（全部）：窄/宽终端、中文/emoji/外部控制字符、主题切换及关闭生命周期通过相关组件和真实 SDK 回归；不增加 render 阶段 I/O，不泄漏定时器或订阅。
- AC7（全部）：受影响测试、typecheck 和完整检查记录实际命令、结果及未运行限制；同步更新必要用户文档。
- AC9（阶段3参数补充）：复用共享卡片/专用展示，不重新设计通用 Arguments/Output 样式；运行中和结束后的工具均可经紧凑入口查看保留参数，明确 complete/truncated/unavailable，不伪装全量历史可用，不现场读文件生成 edit 预览。
- AC8（R4）：详情页打开期间停止/自然完成/失败均可观察到明确终态文本和颜色变化，无需关闭重开；旧工具实时计时停止，不残留 Running 误导，输出与历史锚点保留；尚未实际退出的清理状态不被伪装成退出完成。

## 不在本次范围

- 将主 Agent 整个 TUI 或编辑器嵌入详情页。
- 改变 workflow 子 Agent 的 steering 权限、并发策略、wait/通知/结果消费语义。
- 新增附件输入、完整多行编辑器、队列撤回/编辑等交互，除非另行确认纳入。
- 无界加载完整 transcript、无界保留完整工具输出，或修改已归档任务。

## 已确认决策

- 用户选择：展开当前已加载的全部有界内容，取消显示层额外的 40 个视觉行上限；源数据截断仍明确提示，不自动加载全部输出。
- 保留 source/page/history 预算，展开不触发无界读取。
- 用户最终确认队列改为固定高度的独立滚动区，替代 earlier pending 数量行点击展开方案：正文最多 3 行（少于 3 条按实际数量，小终端 1 行），无消息时收起；标题显示 Pending 总数与当前范围，细滚动条提示剩余内容。鼠标滚轮按会话区/队列区分别路由；Tab 切换区域焦点、↑↓ 滚动当前区域，标题颜色表达焦点，输入框打开时独占输入。默认跟随末尾，手动浏览后新消息不抢位置。点击待处理消息在现有输入区域只读查看完整内容，不改变投递顺序或自动发送。
- 已认可基本提交/接收表现：提交后内容立即出现在待处理区，接收后移入普通 User 会话；失败保留原文并标记 Failed。用户确认点击失败消息恢复原文到输入框，修改后手动发送，不自动重发；成功入队后替换对应失败记录，不在恢复原文时提前删除。
- 用户要求详情页维持颜色区分，并采用紧凑布局。状态、正文、次要统计通过现有语义主题颜色区分；不依靠增加标题、空行和大段提示表达状态。
- 用户确认工具卡片标题布局：工具名、路径/命令、状态和耗时使用主 Agent beautify 风格的紧凑标题区；运行显示 elapsed，完成优先宿主 execution duration，颜色保留强调/次要/状态区分；并行调用分别计时。窄屏先截断路径，保护状态/耗时；停止后未完成调用标记 Interrupted 并冻结 elapsed；Agent 总耗时留在底部统计行。
- 用户确认终态提醒：复用顶部固定单行标题栏，以 Agent 名称＋状态替换 Task Panel · Detail，不再新增重复标题；运行中普通背景，完成成功色背景，停止/中断警告色背景，失败错误色背景，整行铺满宽度并持续保留至离开详情页。使用主题适配的柔和背景与可辨文字/图标；不改变正文或底部区域背景。

## 最终交互决策

- 队列与计时/终态布局已确认；工具默认策略最终获批：read/grep/find 摘要，write 成功摘要，edit 变更摘要，bash/通用输出与失败正文最多 3 个视觉行，点击展开已加载的有界内容。
- 用户补充并最终批准阶段3参数方案：复用公共 ToolExecutionComponent 和已审计 beautify 展示 factories，保留已批准紧凑默认策略；展开优先工具专用原有布局，提供紧凑独立“查看参数”入口展示已加载有界参数，超限明确提示，不添加固定 Arguments/Output 分区，运行中也可查看。
- 只读全文查看退出沿用 Esc 返回原区域，不发送、撤回或编辑待处理消息。
