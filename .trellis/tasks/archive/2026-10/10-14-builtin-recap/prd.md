# 内置 Recap 与会话功能目录收纳

## 目标与背景
将外部 `@tifan/pi-recap` 内置为独立扩展，生成用于恢复工作的短摘要。复用已完成的 [Session Name](../10-14-builtin-session-name/prd.md) 公共请求机制，两个插件统一收纳但保持独立入口、配置和状态。上游 0.4.8 行为证据见 [current-behavior.md](evidence/report.md)，最终需求以本文为准。

## 已确认需求
### R1 目录与归属
- 保留 `extensions/session-name.ts`，新增 `extensions/recap.ts`；实现与测试归入 `extensions/session-assist/{shared,session-name,recap}/`。
- 移动命名实现及更新引用，不改变其已验收的行为。共享请求机制，不混用计数、标题保护、摘要状态或提示词。

### R2 配置与命令
- 命名沿用 agent 根目录的 `session-name.json`；Recap 使用同目录 `recap.json`。
- Recap 必须显式配置 `model` 和 `thinking`，缺少任一项即不可用，不跟随当前会话、不选择默认模型或静默回退。
- 行为配置：`automatic` 默认 true，`idleMinutes` 默认 5，`maxContextChars` 默认 32000；缺少必需模型参数的默认状态并非可生成状态。
- 仅保留 `/recap`（立即生成并显示）及 `/recap config`（查看/修改配置，显示缺失或无效项）。补全说明用途；未知参数提示 `Use /recap or /recap config.`，不保留 status/help。
- 不读取、迁移或自动删除旧 `extensions/pi-recap.json`。它原本不在同步清单，无同步项需删除。新配置由插件拥有，不在清单中硬编码个人模型。

### R3 触发与展示
- 当前会话最终结束后默认等待 5 分钟，以 `agent_settled` 为最终结束边界，不用 `agent_end`；最终结束本身重置空闲起点，不能将运行中的静默时间折抵这 5 分钟。
- 可观察到的普通对话输入（含排队输入）、Pi 正文/thinking/工具参数增量、工具开始/部分更新/结束都记录活动并重置空闲窗口；运行、自动重试、排队续跑和压缩期间不生成。后台任务本身不阻塞，通知触发主会话续跑时取消旧 Recap。
- 无法通过公开事件确认已结束的输入处理/导航操作，保守取消旧请求并暂停自动资格，等下一次正常 `agent_settled` 重建窗口；不按 idle 猜测异步 handler 已返回，不承诺取消导航或被消费输入后自行恢复。用户中止运行（aborted settled）不自动生成；手动 `/recap` 与恢复会话例外仍独立保留。
- 每个空闲窗口只自动尝试一次，失败不循环重试；Recap 自己的请求、通知、持久化和 UI 更新不算对话活动。恢复会话缺失/过期时的自动生成保留为无需等待 5 分钟的例外，但仍受运行状态和上下文身份检查约束。
- 这是当前会话的可观察活动检测，不是整个 Pi/操作系统空闲或离席检测，不监听未提交的键入；不承诺覆盖所有 slash 命令、被其他扩展提前消费的输入和直接 `!`/`!!` 的完整执行状态。公开接口缺口必须说明，不能用私有事件或接管其他插件补齐。
- 恢复会话时复用仍有效的已存摘要；过期或缺失则自动生成。空会话不请求。
- 关闭自动生成后仍可手动生成并恢复显示有效的已存摘要。
- 摘要显示在编辑器上方，新输入隐藏。摘要存于会话扩展状态，不进入 LLM 上下文、不修改主对话。

### R4 请求与正文
- 使用公共 `streamSimple(...).result()` 请求，Recap 使用自己配置的模型和思考等级；请求开始时捕获参数，配置变更影响后续请求。
- 120 秒总截止时间；不照搬上游 `maxTokens=160` 或 `cacheRetention=none`，不删除 payload 推理字段。
- 独立摘要 systemPrompt + 文本化有效上下文，不以主会话缓存复用为目标，不启动工具执行循环。
- 单行纯文字，目标约 160 字符、尽量不超过 240 字符；先写用户目标，再补有用的状态、决定、阻塞或下一步。
- 语言要求只写 `Use the user's language, inferred from their messages.`，不增加多语言说明。

### R5 上下文预算
- 使用当前分支完整有效上下文，尊重已有压缩，不恢复压缩前历史。用户输入、agent 正文及压缩/分支摘要为核心；工具调用和上下文内执行记录为辅助，省略 thinking 和原始图片。
- 工具结果每条最多 100 字符。材料总上限由 `maxContextChars` 控制，默认 32000 字符，不是精确 token 数，也不是输出预算。
- 超限时从最早的工具调用及结果开始删除；工具信息删完仍超限，再裁减最早正文，优先保留近期内容。保留省略标记，格式及标记计入上限，不额外调用模型压缩，不提供最近 N 轮配置。

### R6 失败与生命周期
- 配置缺失、非法或模型不可用以及请求失败，都需用户可见消息，包括自动触发；不自动重试、不覆盖已保存摘要。
- 失败通知必须显示具体原因及失败后的行为，不能只有“生成失败”：公共请求层保留 SDK 返回的 `errorMessage`、抛出异常的 message 和超时原因；确无详情时才使用明确兜底。自动与手动触发遵守同一详情合同。
- 展示详情需清理终端控制字符、按需脱敏凭据并合理限制长度，但不得因此将全部 provider 详情隐藏；不得展示请求 headers、完整 payload 或堆栈。
- 新输入/运行取消计时及旧请求；会话/分支变化、压缩、重复请求、取消及 shutdown 必须围栏迟到结果和旧通知，不能将旧摘要展示或保存到新上下文。
- 活动记录与生成资格分离。请求前和返回后、保存/显示前都检查当前 runtime/session/branch、活动/操作版本、有效材料身份、idle/pending 状态和 Recap 请求所有权；仅 abort 不等于迟到结果安全。手动压缩完成/失败须根据公开事件重新评估，无法确认完成的导航/输入采用用户确认的保守暂停直到下一正常 settled；不能只等下一次 settled 而漏掉可观察的手动压缩，也不能将 before 事件当成操作已成功。
- 不可用不等于失败生成摘要；状态和实际副作用须一致。取消/过期请求不应向新上下文报告错误。

### R7 Session Name 错误详情修复
- 本任务增加独立修复阶段：自动命名和手动刷新均显示具体失败原因，保留旧标题保护、自动失败后等待 N 次用户输入的节奏及取消/过期围栏。
- 不将此修复混入 R1 的纯目录移动，也不改变命名模型、思考等级、prompt、上下文、缓存或配置语义。
- 当前两层丢失及既有测试的反向约束证据见 [error-detail-diagnosis.md](evidence/report.md)；原回归中“全部隐藏 provider detail”的断言须替换为正常原因可见、敏感内容不泄露的断言。

## 验收标准
- [ ] A1 / R1：两个独立入口各注册一次，嵌套模块不被加载为扩展；命名原回归通过。
- [ ] A2 / R2：配置可读写且保留无关字段，缺任一必需项不发请求；无默认/跟随回退；只有两个命令，取消配置不写入。
- [ ] A3 / R3：手动、最终 settled 后完整一次性空闲窗口、活动重置、恢复例外及自动关闭行为通过测试；运行/重试/排队续跑/压缩不生成，后台续跑取消旧请求；接口覆盖边界明确，扩展状态不进入 LLM 上下文。
- [ ] A4 / R4：实际公共 SDK 调用模型/思考参数正确，独立 prompt、不执行工具、120 秒截止及取消通过验证；正文语言/单行/长度约束有测试。
- [ ] A5 / R5：100 字符工具结果及总预算严格遵守；先删旧工具再裁旧正文，Unicode/超长单条/省略标记边界有回归。
- [ ] A6 / R6：自动/手动失败显示具体原因并保留存储；分别覆盖 SDK `errorMessage`、抛出异常、超时及无详情兜底，脱敏/控制字符清理不吞正常原因；无重试循环；输入、切换、压缩和晚返回不会污染新上下文，取消/过期不通知，focused 测试自然退出。
- [ ] A8 / R7：命名自动/手动失败详情可见且旧标题不变；自动失败仍等 N 次输入，不在每次 settled 重试；取消/过期不通知；原命名其余回归通过。
- [ ] A7：外部包移入 conflicts，中文 README、根目录 docs 和来源许可证完整，实际 host loader、离线 SDK 验证、独立审查及受影响完整检查通过。
