# 内置会话命名与 Recap

## 目标
将外部 `pi-session-name` 与 `@tifan/pi-recap` 按顺序迁入 preset，解决旁路模型请求固定关闭思考导致的兼容问题，并让会话标题随实际工作更新。

## 任务地图与顺序
1. [内置 Session Name（已完成）](../10-14-builtin-session-name/prd.md)：手动刷新、可配置 N 轮自动评估（默认8）、手动标题保护、完整有效上下文；公共请求已建立并验收归档，不重复实施。
2. [内置 Recap（剩余实施）](../10-14-builtin-recap/prd.md)：独立配置 model/thinking；按最终 settled 后完整空闲窗口生成摘要。按其 S1 纯目录收纳 → S2 公共错误详情及命名独立修复 → S3 Recap → S4 独立审查/整体检查推进。

两个子任务分别规划、实施、验证；父任务不直接执行产品代码，只汇总已归档命名证据及 Recap 完成后的跨插件验收。已确认 Recap 产品设计和实施顺序；不能把命名旧验收当成移动/共享接口修改后无需回归的证据。

## 已确认的跨任务约束
- 模型调用共用 Pi 公共 `ctx.modelRegistry.streamSimple(...).result()`，等待完整结果而非流式展示。Session Name 跟随当前模型及 `pi.getThinkingLevel()`；Recap 必须显式配置自身 model/thinking，缺失不可用，不跟随、不回退。均不固定 `off`、不默认删除 payload 推理字段。
- 提示词放独立旁路请求的 `systemPrompt`，会话材料作为数据；不修改主会话 prompt，不触发额外 agent 对话。
- 不因输出文字短而人为设置小 `maxTokens`，避免推理耗尽预算而没有正文；默认交 Pi/模型处理，并明确超时、取消、失败语义。
- 两个功能共用模型调用机制，但标题与 Recap 的内容提示词、触发、状态和展示各自拥有。
- 迁移时使用 preset 的 conflict/package 机制防止重复加载；不自动修改个人配置、执行 install/sync/reload、提交或推送。

## 验收
- [ ] 两个独立内置入口只加载一次；嵌套公共模块不被发现为扩展。
- [ ] 手动与自动命名以及 Recap 均使用同一个已验证的请求模块，无独立认证/HTTP 实现。
- [ ] 思考设置变更作用于后续请求，当前请求捕获稳定参数；不改变主对话模型配置。
- [ ] 两个子任务分别通过离线测试、实际 SDK 契约验证与独立检查；移动目录/公共请求修改后的命名回归重新通过。
- [ ] 两插件共同运行时各自持有配置/计数/controller/epoch；命名的中性 metadata 不使 Recap 过期或循环；同边界请求参数独立正确，输入/压缩/切换/shutdown 清理互不干扰。
- [ ] 外部包替换、中文 README、来源/许可证信息完整；不覆盖并行修改。

## 不在范围
修复 Pi SDK、所有适配器模型元数据、主对话调用、修改其他第三方插件、自动用户安装、推送发布。
