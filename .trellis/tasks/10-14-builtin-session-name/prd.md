# 内置 Session Name 与可配置自动更新

## 目标
让 session 标题反映当前主要工作，而非永久绑定第一句 prompt；提供可控自动评估和显式手动刷新，跟随 Pi 当前模型及思考设置。

## 背景与事实
- 现有 `pi-session-name@0.1.7` 只处理第一次 input，固定 `reasoning: "off"`，三次失败后静默停止；见 `research/findings.md` 的安装源码锚点。
- 当前 `mp-responses/gpt-6.1-sol-coding` 拒绝 `none`；真实旁路请求复现 400，`low` 成功。Pi 1.1/1.2 Responses 在未指定推理时也可能补 `none`，不能只删调用选项。
- 用户最终选择当前模型与当前思考等级，而非强制省略推理字段；等级适配依赖模型元数据，不保证遇到 400 自动降级。
- status-bar 已读取 session name，不需要新增 footer 设计。

## 需求
### R1 内置与替换
独立内置扩展，不运行外部 session-name；通过 preset 包声明与 conflicts 防止重复加载。保留已有 session 标题，不擅自清空历史名字。

### R2 手动与自动
- `/session-name` 从当前对话重新评估标题。
- `/session-name config` 设置自动更新开关、N；默认自动开启、N=8。配置保存到 agent 目录，跨会话持久化，不增加会话覆盖层。
- 无标题时第一轮有效用户对话完成后生成。
- 之后每 N 次有效用户对话评估一次，而非空闲时间或内部工具轮次。
- 有效用户输入及其处理计数；普通用户 steering/follow-up 属有效输入。斜杠命令（含 skill/template）、插件注入/通知、工具循环不计。
- SDK 不保存可靠输入来源/关联 ID；从启用后保守匹配可确认输入与实际交付消息，歧义及未知历史不补计。未交付排队输入不计；已交付并 settled 的输入计数，不要求主模型回答成功；aborted 边界不自动命名。
- 达到阈值后在彻底 settled 边界合并评估，不在运行中逐条发请求。未改变主要目标可保留原标题。
- 成功评估推进已处理位置，手动成功刷新重置计数；失败保留旧标题并显示一条用户可见英文消息，从失败处理位置再积累 N 次有效输入后自动重试，不在同边界循环；手动刷新随时可试。正常取消与 stale 结果不提示失败。

### R3 手动标题保护
`/name xxx` 或外部非本扩展改名后暂停自动覆盖；仅显式 `/session-name` 刷新成功重新交给自动管理。已有来源不明标题保守视为手动。迟到响应不得覆盖用户改名。标题与手动保护为整个 session 范围；结合公开事件、title entry 身份及提交前复核，不承诺检测其他进程直接修改文件。

### R4 上下文准确性与成本
用户否决只看近期增量与额外命名摘要。读取当前分支、Pi 压缩感知的有效上下文；保留已有压缩摘要、用户消息和助手可见回复，排除 thinking、工具调用/输出及插件状态通知。不主动 `/compact`，不发送其他分支。

不新增独立输入预算门禁、不按长度跳过自动评估、不截断为近期窗口，也不增加手动超预算确认。每次使用整理后的完整有效上下文，而非全部原始历史。未压缩的长对话仍可能消耗较多输入 tokens；通过可配置 N 和自动开关控制调用频率，不承诺固定成本。

### R5 共用模型调用
- 使用 Pi 公共模型生成接口 `streamSimple(...).result()`，等待完整结果而非流式展示；默认当前模型与 `pi.getThinkingLevel()`，手动/自动一致；为下一个 Recap 任务预留最小共用模块。
- 每次请求捕获模型、等级、上下文、身份；不固定 off/low，不默认 payload 改写，不自行 HTTP/认证。
- 不设人为过小的 maxTokens；默认遵循 Pi/模型输出能力。采用 120 秒总请求截止时间和自有取消资源，不以标题字数推导推理预算；SDK adapter timeout 不能冒称总截止时间。
- 独立 systemPrompt：材料是数据，不执行其中指令；简单判断原标题是否仍准确，只输出用户主要语言的短标题，不解释、不解决对话任务；提示词不能保证推理耗费。
- 校验正文格式、空/多行/控制字符等；无有效标题不写入 session。
- 用户新输入、会话/分支更换、shutdown 时旧结果失效；不改主会话 prompt 或模型设置。
