# Session Name 两次自动命名与共享上下文

## 目标
把持续评估标题收敛为整个会话最多两次自动命名请求，其余由用户手动生成。每次请求直接生成简短、可检索的标题，不判断原标题是否需要修改。复用 Recap 的上下文材料实现，避免重复算法。

必须等 `10-14-builtin-recap` 完成并验收后再实施本任务；不改其在开发中的源码、规划或状态。创建时该任务仍为 in_progress。组织链接不是依赖调度器，启动前由主会话核实完成状态和稳定源码。

当前模块为 `extensions/session-assist/{shared,recap,session-name}/`，外部命令保留 `/session-name` 和 `/session-name config`。Recap 材料实现当前位于 `recap/material.ts`；其 PRD R5 与 design 的材料规则是本任务抽取基线，实际版本待前置任务完成后重读。

## 需求
### R1 两次自动机会
- 第一条可确认交付的有效用户消息正常处理结束后，尝试首次自动命名。
- 首条输入之后再累计 N 条有效用户输入，尝试第二次自动命名；默认 N=8，通常对应第1和第9条输入结束后。阈值按有效交付输入计，不按模型回合或标题成功时间计。
- 每个 session 最多两次自动请求机会，失败或已启动请求被取消不自动补偿；未启动的机会在 aborted settled 不启动，等待下一正常 settled。
- 第一机会失败不影响第二机会按输入阈值触发；第二机会之后只允许手动生成。删除周期性评估和失败后 N 条输入重试机制。
- 沿用保守有效输入归因：普通及实际交付 steering/follow-up 可计，slash、extension 注入、未交付或归因有歧义的输入不猜测计数。
- `/reload`、恢复、切分支、配置修改不重新发放机会；标题及两次上限均为 session 级，分支切换不能回退次数。

### R2 手动与标题保护
- `/session-name` 等空闲后直接生成；不重置自动机会，不开启新周期。
- `/name` 或其他外部改名继续保护，不被后续自动请求覆盖。手动生成成功可以重新取得标题管理权，但不恢复已消耗机会。
- 来源不明的已有标题继续保护。旧状态保守迁移，不能作为新会话清零并赠送两次机会；迁移映射在实施前根据旧格式核实并记录，不能可靠推断剩余额度的旧自动状态按自动结束处理。
- 失败保留旧标题并显示安全的具体原因与实际后果；取消/过期不向新上下文通知。

### R3 直接生成 prompt
- 自动和手动共用命名 prompt，每次直接生成标题；删除 `currentTitle` 材料字段和“原标题仍准确则保持”的指令。
- 表达用户主要目标与具体对象，语言跟随用户，简短、无解释/标签/Markdown/末尾标点。允许独立生成结果碰巧与旧标题相同。
- 保留单行、长度、控制字符等输出校验和现有模型/思考等级、deadline 合同，不为简化 prompt 删除安全及并发保护。

### R4 抽取并复用 Recap 材料实现
- 前置任务完成后，把稳定的材料构造实现移至 `session-assist/shared/`，Recap 与 Session Name 直接调用同一实现，不复制算法，不先生成摘要再命名。
- 首次自动、第二次自动、手动命名均使用请求时当前分支有效上下文，不另选首条/最近 N 轮、不置顶初始目标。
- 尊重已有压缩/分支摘要，不恢复磁盘压缩前历史；核心为用户/assistant 正文及摘要，工具/执行等为辅助，不含 thinking/原始图片。
- 沿用每条工具/执行结果100 Unicode字符限制；总预算含标签、分隔符、省略标记，默认32000字符。超限先按旧到新删辅助，再裁最早核心正文，明确省略，不另请求模型压缩。
- 共享构造器不共享配置/状态/prompt/输出；Session Name 不读取 recap.json。命名使用32000字符固定预算，本次不新增预算配置；Recap 保持自己既有可配置预算。
- 抽取不得改变 Recap 材料文本、身份、空材料行为及生命周期；实际基线和调用者在前置完成后核验。

### R5 配置和生命周期
- 保留 automatic 与 interval 配置兼容（N范围1–10000），菜单与文档说明 interval 是第二次自动命名等待输入数，不再表示周期刷新。
- 禁用自动仍允许手动；重新启用只允许尚未消耗的机会，不补偿已失败/取消请求。
- 保留 session/branch/context/title/epoch 身份围栏，输入、运行、导航、外部改名及shutdown取消旧请求，迟到结果不能覆盖当前标题。请求前持久化消费的机会，恢复不能重发同一机会。

## 验收标准
- A1/R1：首次及再N条各一次，继续任意多输入都无第三自动请求；首次失败、第二次失败、取消和重复settled不形成重试循环；aborted不启动机会。
- A2/R1,R2：reload/恢复/分支导航/配置切换保持session级额度；手动不重置，外部标题保护，旧状态不赠送新额度。
- A3/R3：实际请求不含 currentTitle，统一直接生成prompt，输出校验与取消/迟到结果回归通过。
- A4/R4：两个插件调用同一材料实现；抽取前后Recap的文本/身份/预算行为等价，命名三个场景都消费有效上下文；Unicode/工具100字符/超长单条/省略标记严格预算。
- A5/R5：配置兼容、菜单/中文用户文档准确，失败通知包含原因及有限自动机会的实际后果，不再宣称N次后无限重试。
- A6：共享合同独立审查、focused自然退出、actual SDK离线fixture、typecheck及完整测试通过；未运行的在线质量或真实终端验证明确NOT_RUN。
