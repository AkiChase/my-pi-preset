# 统一 Session Name 与 Recap 的模型配置模式

## 目标
两个插件统一提供“跟随主会话”与“独立配置”，无需为命名或回顾切换主对话模型。

## 背景与决定
- Session Name 当前从 `ctx.model` 和 `pi.getThinkingLevel()` 捕获参数，仅配置自动开关及输入间隔。
- Recap 当前显式要求 `model` 与 `thinking`，菜单已有已认证文本模型选择及思考等级校验。
- 用户确认：两个插件均支持模式选择，Recap 未配置模型时也默认跟随主会话。
- 现有 Recap 独立模型配置继续沿用，不因新增默认行为被覆盖。

## 范围与要求
1. 两个全局配置文件支持 `modelMode: "follow" | "custom"`。未显式设置模式且存在独立模型配置时沿用独立模式，否则默认跟随；显式模式优先。
2. 跟随模式同时使用请求发起时主会话的模型和思考等级，不允许独立覆盖思考等级；保留独立配置字段供切回使用。
3. 独立模式要求有效的 `provider/model-id` 和显式、模型支持的思考等级。不可用、未认证或不支持文本的模型报错，不静默回退。
4. `/session-name config` 与 `/recap config` 显示当前模式，提供跟随入口及独立模型/思考等级配置。选择独立模型需要补选思考等级时，两步一起保存；取消任一步不写入。单独选择思考等级仅面向独立模型。
5. 模式切换和字段修改使用新鲜读取的局部补丁保存，保留未知字段；坏 JSON 不覆盖。请求捕获参数后不因主会话模型切换或菜单保存而换参数，原有输入、导航及关闭的失效规则保持。
6. Session Name 的两次自动机会、标题保护、固定材料预算；Recap 的空闲窗口、已保存回顾复用、预算和展示顺序均保持。没有模型时不发请求；Session Name 跟随模式在主会话无模型时不消耗自动机会的原有规则继续成立，独立可用模型不依赖主会话是否有模型。
7. 更新两份中文用户文档、相关测试与必要的英文规范；文档只描述当前功能，不写迁移历史。

## 验收标准
- 配置缺失时两个插件均跟随；现有 Recap 独立配置无需修改仍使用原模型和思考等级。
- 两种模式在两个插件的手动及自动请求中生效；主会话设置不被改写。
- 配置菜单可选择已认证文本模型和支持的思考档位，可切回跟随并保留独立值。
- 非法模式、非法独立参数、不可用模型没有意外请求或回退；取消、导航、认证变更不会写入无效配置或迟到结果。
- 原有次数、标题保护、空闲调度与存储回归通过；专项目录及共享对话自然退出测试、类型检查和全量套件通过，或如实记录环境阻塞。

## 排除项与风险
不增加项目/单会话覆盖、独立环境变量、供应商回退、额外材料配置，不修改 SDK 或 preset 同步机制，不安装依赖、不 push、不归档。`pnpm-lock.yaml` 已有修改不属本任务。
Recap 默认跟随会使未配置模型的用户在既有自动触发时产生额外请求；文档说明费用。离线测试不证明在线生成质量或真实终端外观。

## 授权
已获任务创建、规划及最终方案实施许可（用户明确“开工”）。由主会话实施；因新增共享配置契约，主会话自审后追加独立 `trellis-check` 审查。按一个耦合阶段验证并本地提交；不包含安装、个人配置更改或归档。
